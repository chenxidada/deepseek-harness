## 关键发现

### 🔴 Must-Fix
（无）— 未发现违反 AD-ECP-3/6/7/8/9/10/11 或 Constitution §2/§7 硬约束的架构漂移。

### 🟡 Should-Fix
1. **历史行操作密度偏离 `ui-visual-spec.md` §5.5**：当前每行常显 Continue +「删除」。规范默认「hover 显示行尾 ⋮ 菜单（含删除/Continue）」；**禁止**多入口并列喧宾。建议改为 hover/焦点显现的溢出菜单（或等价弱化），并保留层 A 可测 testid。
2. **历史空态缺引导动作**：§5.5 要求短文案 + 新建/开始引导；现仅「暂无历史会话」。应补 CTA（如触发 `ui/tab-new` 或关闭历史后聚焦 composer）。
3. **Markdown 共享路径应用 Vite alias**：`MessageList` 使用 `../../../src/markdown/safe-markdown.ts`，而 `vite.config.ts` 已提供 `@dsh/safe-markdown`。统一走 alias，避免 webview↔Host 相对路径脆弱依赖。

### 🟢 Observations
- AD-ECP-6 主路径正确：溢出「删除会话」与历史「删除」均 `openDeleteConfirm` → modal → `ui/delete-request`；Host `runDeleteConfirmed` 跳过原生二次确认。`action/delete` → 原生 `confirmDeleteConversation` 仍为遗留 Host 能力，React 未用作唯一确认，符合「原生可作为增强、不得替代 webview 契约」。
- 停止中 DOM（R7）与 design 一致：`data-composer-state` 不变 + `btn-stop[disabled]` + status「正在停止…」。
- 消息气泡弱描边（对齐+轻底衬），符合 UI-AC-20 / §5.2 相对 thin HTML 的改造方向。
- Timeline 打开走 `workbench.view.extension.dsh` 属已记录偏差，不推翻 AD-ECP-7。
- Phase Entry Gate 债务 GAP-ECP-001…007 + DEBT-ECP-001 已迁「已解决」；活跃表空——与「本 Phase 优先解决」一致。
- `bridge` 仍含 `action/delete` 类型：建议后续清理或文档标明「非 React 主确认路径」，避免下游误用。
