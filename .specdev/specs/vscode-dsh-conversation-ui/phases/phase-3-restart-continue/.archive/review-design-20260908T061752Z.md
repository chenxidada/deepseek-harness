## 偏差与设计对齐说明

implementation.md 记录：Continue 经 `sdkSessionResume`（登记 SDK session Map）而非 bridge 内直接 `ctx.agents.resume`。这与 **AD-CU-12「勿扩 SDK stdout create」** 及既有 dispose 服务模式一致，下游仍经 bridge `session/resume`，**不构成架构违反**。

## 关键发现

### 🔴 Must-Fix
（无）

### 🟡 Should-Fix
- **Conversation Webview HTML 未消费 Continue / 查看更多 chrome**：`chat-panel-provider.ts` 内嵌页在 `panel/state` 时忽略 `continue` 与 `deferredRestoreCount`，也无按钮 `postMessage({ type: 'action/continue' | 'action/restore-more' })`。Host 协议、命令（`dsh.continueConversation` / `dsh.restoreMoreTabs`）与 L2/L3 钩子已满足 AD-CU-8 能力与可调用面；但 AD-CU-1「跟 `panel/state`」对新增 chrome 字段在真实 Webview 呈现层未闭合（L4 非门禁，仍建议补齐以免协议字段成为死载荷）。

### 🟢 Observations
- **derive-only**：Gate 锁定 `same-id`；`continueConversation` 仅预留 banner，未做同 tabId 换绑新 `sessionId`（AC-67 完整派生）。当前探测路径不可达 derive-only，可接受；若日后 Gate 改 derive 需补实换绑。
- **`pendingRestoreLatch`**：未连时置位并推 waiting-host；产品冷启路径是 `startSession` 先连再 restore。Latch 不在 Host 状态变化时自动重入 hydrate——依赖再次调用 `restoreOpenTabSet`（L2/测试路径已覆盖）。
- **GAP-001**：registry 已标已解决；bridge resume + `sdkSessionResume` 接线与设计组件图一致。
- **未改** `packages/core/agent-loop*`；SDK stdout create 路径保持 create-only。
