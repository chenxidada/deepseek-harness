## 关键发现

### 🔴 Must-Fix

1. **`assertion-map.md` 表头偏离 design.md §数据模型 2 定稿的列 schema**

   design.md 定稿台账列为 11 项（原文件 / 原标题 / 处置 / 理由码 / `keepChecks.K1/K2/K3` / `K 依据` / `privateSymbols` / `replacementCap` / `关闭依据` / 新 CAP- 编号 / `weakened`），Phase 1 产出「表头 + 全量用例声明行」的骨架。实现实际表头仅 6 列，存在两处偏差：

   - **缺 6 个定稿列**（`assertion-map.md:6`）：
     - `keepChecks.K1/K2/K3`（AC-27 ① 强制三 bool）
     - `K 依据`（AC-27 ②，`K=true` 行必须给 `路径:行号`）
     - `privateSymbols`（AC-29 ②，D2 行强制）
     - `replacementCap`（AC-9/AC-12，D3 行强制）
     - `关闭依据`（AC-9/AC-12，D4 行强制）
     - `weakened`（AC-29 ③ 强制 bool）
   - **多出 1 个未定义列** `所属域`：design.md、requirements.md AC-9、spec.md 三份权威文档均无此列。它引入第二份「域归属」真相源，与 `capability-domains.json` 的 `absorbed` 冗余，一旦 Phase 2 逐行回填时两边不一致即产生漂移，违反决策 3「台账是唯一追溯载体」的单一真相源原则。

   影响：Phase 2 的 implementer 以本骨架为输入，若表头缺 `keepChecks`/`K 依据`/`weakened` 列，则 AC-27/AC-29 要求的字段无处落盘，必须在 Phase 2 重建表头；这属于「定稿数据模型在骨架阶段即被改写」。按「违反 design.md 中明确声明的架构决策 → MUST-FIX」判定。

   建议：表头补全 design.md §数据模型 2 的 11 列（保留 `所属域` 与否需用户/调度者决策——保留则须回写 design.md 修订记录，删除则与定稿严格一致）。

### 🟢 Observations

1. **`scripts` 字段的逐域映射是 Phase 1 推断，非 design.md 定稿**。design.md §数据模型 1 只给 `session-host` 示例（`run-layer-v-smoke.sh` + `layer-v-driver/extension.cjs`），未给 16 文件逐域映射。实现落 `session-host=4` / `test-harness=12` / 其余 8 域 `[]`，16 文件覆盖无遗漏无重复（4+12=16，与 repo-exploration §3.4 一致），已作为 D-1 偏差记录。AC-19 的完整 4 类分层 + 唯一归属域属 Phase 3 写面，届时若裁定共享文件（如 `layer-v-support/layer-v-runtime.sh`）改归他域需更新本字段。

2. **`entryAssertions` 的 `entrypoint` 字符串是 Phase 1 骨架推断**。design.md §数据模型 1 定义结构为 `{entrypoint, caps}` 与 entrypoint 语义（命令 id / 导出符号 / IPC 消息 / 工具名），但未枚举每域精确字符串。实现的 10 个 entrypoint（`activate`/`dsh.test.*`/`dsh.showPanel`/`message-bridge`）与 repo-exploration §3.3 的入口线索一致；`caps: []` 留空符合 spec.md「caps 待 Phase 2 回填」约定。entrypoint→caps 映射的语义正确性归 `reviewer-correctness`（AC-11）。

3. **`layer-v-capabilities-phase3.spec.ts` 未执行 `git add`**（D-2 偏差）。该文件仍为 untracked，与 spec.md 约束「未入库 spec 纳入版本控制（git add）」存在字面偏差；但 D-2 已记录为「用户分派指令硬约束『不 commit、改动留工作区』」所致，且该文件已正确登记进 `absorbed`（test-harness）与台账，AC-2 判定用 `find` 不因未 `git add` 受影响。属流程/范围议题而非设计一致性议题，仅记录。
