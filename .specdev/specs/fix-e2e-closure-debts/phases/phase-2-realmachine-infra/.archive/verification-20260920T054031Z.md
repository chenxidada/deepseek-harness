## 主动问题上报（AC-19）—— 为何不是 PASS

本 Phase 判决为 **PARTIAL**，根因是**环境缺 `DEEPSEEK_API_KEY` 导致 model 批真机运行时验证不可执行**，而非实现缺陷。分条如下：

1. **AC-4（DEBT-2 fork 子会话首轮 retry 往返）真机未验**：DEBT-2 已按 AC-13 如实登记为残留（SDK `createForkedSession` 无 `agentPreset` 覆盖 seam，改测试 harness 无效、改 SDK 属越权）。verifier 已独立确认登记诚实（`server.ts:285/473/482/493-494`），该项**不是本 Phase 的新失败**，但「子会话以 retry 提示词完成首轮真实模型往返」的验收在缺 key 下无法独立证明。
2. **AC-5（DEBT-3 #18 流式增量稳定捕获）真机未验**：`intervalMs:150→50` + 六段分段指令的静态改动已落地且未放宽 `requireIncrement`，但「连续 2 次 run 稳定 `sawStreaming/sawGrowth=true`」这一核心验收需真机 + key。
3. **AC-7 运行时（`cap-delegate-subagent-model` 真实委托）真机未验**：静态链路（`requiresModel:true` + `sendPrompt`→`listChildren`→`$assistantContains`）就位，但「模型真实调用 `subagent` 工具委托子 Agent」需真机 + key 判定；若真机模型不调用 subagent，则方案 A 的 R5 端到端可达性假设不成立，需按 AC-13 补登记，**不得回退 `requiresModel` 收窄冒充闭环**。
4. **AC-8 运行时 model 批（subagent 后 13 项 `readonly-live` 复位）真机未验**：污染②（`resetForTest` 清 context + 关子 tab）的**代码路径已静态确认**，nonmodel 批的污染①（idle 复位）已真机通过，但污染②在 model 批（真实 subagent 委托后切回 live）的运行时效果缺 key 未验。
5. **AC-9 全链 42 项一键跑通真机未验**：nonmodel 批（18 项）exit 0 与 model 批（24 项）exit 3 分别验证，但「42 项串行、无状态污染、聚合 exit 0」的全链终验缺 key 未执行。

以上 5 条均为「缺 key」这一**环境约束**所致，均非实现缺陷；静态 + nonmodel 真机 + 回归部分全部真实通过。
