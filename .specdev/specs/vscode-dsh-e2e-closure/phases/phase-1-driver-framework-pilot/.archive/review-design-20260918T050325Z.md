## 关键发现

### 🔴 Must-Fix
（无）

### 🟡 Should-Fix

- **[AD-2 机制偏离] 断言原语以「复制」而非「require 复用」落地，造成 13+ 原语的第二份拷贝。**
  - design.md AD-2 明示「复用其 `StageError` 退出码分类与断言原语（**require 复用**）」，API 域又写「复用（require/import 形态）」。
  - 实际实现把 `StageError` + 三工厂（`linkFailure`/`harnessError`/`skipNoCredentials`）+ `safeJson`/`unwrap`/`truncate`/`nowIso`/`sleep` + `pngVerdict`/`sha256Of`/`runCapture`/`probeScreenSize`/`outputFreeTemplateViolation`/`resolveCaptureTool`/`captureScreenshot` **复制**进 `capability-runner.cjs`，未 `require` 既有 `layer-v-driver/extension.cjs`。
  - **语义忠实度（这点必须说清，用户要求核对）**：逐字节比对，`StageError`（`capability-runner.cjs:61-77` vs `layer-v-driver:97-114`）、`safeJson`（`:97-120` vs `:139-159`，depth=6 / slice=50 / `abort|resolve|reject` opaque 键一致）、`pngVerdict`（`:279-290` vs `:550-561`，size<1000 + PNG magic）、`sha256Of`（`:293-299` vs `:564-570`）**逐字节一致**；`resolveCaptureTool`（`:351-415` vs `:727-801`）候选顺序/模板契约/返回字段语义一致。结论词汇 0/1/2/3/4 跨「两驱动 + 共享 shell 库」**三方一致**。**因此不是「另造一套新语义」，而是「忠实复刻语义 + 另存第二份代码」。**
  - **偏离为何在技术上几乎被迫**：既有 `layer-v-driver/extension.cjs` 仅 `module.exports = { activate }`（`:2441`），上述原语**全部未导出**，且文件顶部 `require('vscode')`。要做到「require 复用」只有两条路：(a) 改既有文件导出这些原语 —— 违反 AD-2 另一条「不改既有 `extension.cjs`」；(b) 先把原语抽到共享模块 —— 属对「已验证交付物」的重构，超出 Phase 1 范围。即 design.md 内部存在「不改既有文件」与「require 复用」的张力，实现者选择「镜像到 dependency-free 模块」并已在 `capability-runner.cjs:13-18` 头注释显式声明该取舍（可脱离宿主测试）。
  - **后果与建议**：当前是 DRY 违规，风险在**未来漂移**——若 `layer-v-driver` 日后修 `resolveCaptureTool`/`pngVerdict` 的 bug，新驱动不会自动继承，两套「结论词汇」可能分叉。建议二选一：(a) 在 design.md「设计修订记录」补一条，把 AD-2 机制从「require 复用」改为「镜像语义至 dependency-free 模块」，并把「两驱动原语重复」登记进 `tech-debt-registry.md` 供后续合并；(b) 后续 Phase 把 13+ 原语抽成 `layer-v-support/` 下的共享 CJS 原语模块，两驱动都 `require` 它。**此属需要调度者/用户拍板的机制决策，故定 SHOULD-FIX 而非 PASS。**

### 🟢 Observations

- `capability-runner.cjs` 的 `captureScreenshot(capture, fileName, artifactDir)` 比 `layer-v-driver` 版本多一个显式 `artifactDir` 形参（原版用模块级 `ARTIFACT_DIR`）。这是对「纯模块无固定产物目录」的合理参数化，语义不变，非问题。
- `run-layer-v-capabilities.sh` 的 `main` 顶部新增 `--capability <id|group>` 参数（S-2 单项复验，requirements.md 场景），实现为对编排脚本的增强，与 spec/design 契约不冲突（implementation.md 已声明「非偏差」）。
- 新驱动 `package.json` 的 `activationEvents` 为 `["*","onStartupFinished"]`，与既有 `layer-v-driver/package.json` 完全一致，无额外差异。
