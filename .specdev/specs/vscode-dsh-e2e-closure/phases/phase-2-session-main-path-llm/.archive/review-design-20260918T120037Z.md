## SDK server 继承机制 — 与既有 preset 机制一致性（重点）

`createForkedSession`（`server.ts:462-501`）与仓库内**子 Agent 继承 preset 的权威先例** `subagent/child-agent.ts` 逐点对齐，未重复造轮子、未误用 `mount`：

| 环节 | 先例（`subagent/child-agent.ts`） | 本 Phase（`server.ts`） | 判定 |
|:---|:---|:---|:--:|
| 取父 preset id | `parent.ctx.get('agentPresets')?.composedPreset(parent.ctx)`（`child-agent.ts:144`） | `presets?.composedPreset(parentAgent.ctx)`（`server.ts:473`） | ✅ 同一原语 |
| 写 durable header | `meta.agentPreset`（`child-agent.ts:147`） | `meta.agentPreset: parentPreset`（`server.ts:482`） | ✅ |
| 子创建窗内 join | `composeFrom(childCtx, parent.ctx)`（`child-agent.ts:204`） | `setup: childCtx => presets.composeFrom(childCtx, parentAgent.ctx)`（`server.ts:493-495`） | ✅ 同一原语 |

- **`composeFrom`（join）而非 `mount`（resolve+compose）是正确选择**：分叉子会话必须加入父会话**同一代** standing composition；`mount` 会按 id 重新 `resolveMountable`→`ensureStanding`，preset 文件若在父启动后被编辑/删除，会给出不同代或直接失败（`agent-presets/src/index.ts:429-464` 对两者语义的区分正是此意）。`createSession` 用 `mount` 是因为它挂**默认** preset 建**全新顶层**会话，语义本就不同。
- **未遗漏 mount 语义**：`composedPreset` 负责 durable header 值、`composeFrom` 负责实际 join，二者都派生自同一 `standingMountFor(parentAgent.ctx)`，无冗余、无缺口。
- **`forkSession` 从 `this.ctx.sessions.get()` 切到 `this.sessions.get()`（`server.ts:294`）是收敛而非偏离**：`prompt`/`cancelSession`/`disposeSession`/`resumeSession` 全部走私有 `this.sessions` Map（`SessionRecord` 含 `handle.agent`）；只有 `Session` 而无 Agent 的 `SessionStore` 反而是孤例。此切换为拿到 `parentAgent` 以继承 preset 所必需，且使 `forkSession` 与其余会话方法一致。

### 🟢 Observations

- **[文档保真无关 / 维护性] `agentPresets` 内联结构类型重复**：`createSession`（`server.ts:399-402`）声明 `{ defaultId; mount }`，`createForkedSession`（`server.ts:469-472`）另声明 `{ composeFrom; composedPreset }`，同一可选服务出现两份按需子集的内联类型。这与 `createSession` 既有写法一致、非本 Phase 引入，且避免 `sdk/server`→`agent-presets` 硬依赖（合理取舍）；仅提示后续若抽共享 `AgentPresetsLike` 类型可消除两份的漂移风险。**不参与判决**。
- **`assistantText` 语义漂移（已被 DEBT-1 覆盖）**：`capability-runner.cjs:256-266` 的 `assistantText` 用 `out += text`（无分隔符），与 `layer-v-driver/extension.cjs:519-525` 的 `.join('\n')` 存在细微差异；此为 Phase 1 既有镜像，DEBT-1 已在 phase-5 计划「抽共享原语模块消除漂移」，本 Phase 未加重（`assistantStreamingActive` 是 layer-v-driver 无对应物的**新**逻辑，非复制）。**不参与判决**。
- **`$assistantClosed` 未进 `MATCHERS` 静态表**：属参数化谓词（携带 marker），按既有 `$array:N`/`$contains:`/`$assistantContains:` 约定走 `resolveMatcher` 内联分支而非 `MATCHERS` 条目，是正确形态，不是「未走注册表」。
