## 关键发现

### 🔴 Must-Fix
- （无）本 Phase 审阅/撤销 AD、AC-17 门禁、禁 agent-loop、模块落点均对齐 design。

### 🟡 Should-Fix
1. **AD-CCD-6 prune 未挂入产品写路径**：`pruneChangeSnapshots` / `pruneToBudget`（含 reverted-first）已实现，但 settle/`SnapshotStore.write` **从不调用**，软上限 200 MiB 在运行时不会自动生效。建议在 settle 或 write 成功后 best-effort 调用（失败不阻断主路径）。
2. **AD-CCD-6 openTabSet / unreverted 保留未进入 prune 受害者选择**：设计要求 openTabSet/内存 Tab 存活时保留 unreverted blob；当前仅「fullyReverted 优先 → 再最旧 mtime」，超预算时仍可能 prune 开着的 unreverted 会话。建议 prune 传入 open session 集合并跳过（或置于队尾且仅在无其他受害者时考虑）。

### 🟢 Observations
- 删会话清 ChangeStore 经由 `ChangeAttributor.clearSession` → `changeStore.clearSession`（非 `deleteConversation` 直接调用）；行为满足 AD-CCD-6，耦合略隐式，可接受。
- `confirmRevertLaterChanges` 文案含「先处理后续回合」；单文件早 turn 撤销仅确认后撤本条，不自动撤后续——语义偏 UX，非架构违规。
- L2 无 `vscode.workspace.fs` 时 Node `fs` 回退与 Constitution「须经 VS Code API」字面略松，但产品激活路径优先文档层 / `workspace.fs`，与 AD-CCD-10 一致。
