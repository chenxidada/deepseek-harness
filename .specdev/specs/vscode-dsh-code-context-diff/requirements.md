## 产品目标

在侧栏「点开即可聊」之上，交付：

1. **代码引用**：用户可通过选区命令/右键将 `@路径` + 自然语言行范围指针发送给 DSH；DSH **必须**按需读取磁盘内容后再作答（AC-3a，stub 可测）；手输 `@路径` 同样只发指针。**禁止**将文件内容拼接进 user 消息正文。
2. **变更可见可控**：DSH 执行对工作区的创建/修改/删除以变更列表 + diff 挂靠在对应助手消息下；用户可逐文件审阅标记、撤销（含批量与冲突确认）。

**不做**：写盘前审批、语义检索、内容内联注入、编辑器 dirty buffer 同步、扩展 `:lines` 文法、Git 驱动 diff、Timeline 本体重构、在 diff 上再编辑应用、按语言/类型过滤变更列表、同文件中间版本快照恢复。

## 代码引用的产品语义

### 核心原则

- **引用是针，不是内容。** 选区/文件不把正文带入 user 消息，而是将官方 `@路径`（可选自然语言行范围）作为文本发送给 DSH。
- **磁盘即真相。** DSH 读取引用对应文件时以磁盘为准。生成选区引用前，若目标文档脏，扩展先自动保存；**保存失败则必须不生成引用**并提示用户手动保存后重试。
- **模型按需读取，且可测。** 含一个或多个有效引用的一轮交互中，**每个**引用路径须在最终回答前至少出现一次读取工具调用（AC-3a；L2 stub；多 path 不约束顺序）。扩展**禁止**在发送门禁读盘并拼接正文。
- **配置补齐。** ide profile 若缺少等效 `FILE_REFERENCE_PROMPT`，扩展激活后须补齐（AC-3b）；禁止改 agent-loop。

### 统一的引用格式

| 场景 | 消息中呈现的文本 |
|------|------------------|
| `@路径`（手动输入，相对或绝对） | 原样保留，如 `@src/foo.ts` 或 `@/abs/path.ts`（须通过工作区校验） |
| 选区提问（命令/右键） | `@src/foo.ts` + 自然语言行范围 + 用户补充问题，例如：`@src/foo.ts 的 3-40 行` 后接用户提问 |

要点：

- 底层引用仍为官方 `@路径` 文本；**不**引入 `@path:3-40` 文法。
- 行范围用自然语言附着；模型自主决定 read 后聚焦哪些行。
- UI 可将 `@路径` 渲染为引用卡；行范围作描述文本；点击引用卡打开文件时，行号来自**预填时记录的选区元数据**（扩展本地），不靠解析自然语言。

### 与既有 Web 行为的兼容

对齐 Web `@file` 契约（路径作为提示、模型 `read`）。本 Feature **不**另造内容注入通道；若 ide 未挂载文件引用引导，按 AC-3b 补齐。

## 预期范围

### In Scope（全部 Must）

#### A. 代码引用

- 命令 `dsh.askAboutSelection`（及编辑器右键菜单）：
  - 活动文档脏 → 先自动保存；**保存失败 → 必须不生成引用**，轻量提示手动保存后重试；
  - 非空选区 → 激活/复用对话；composer 预填 `@相对路径`（或工作区内可校验绝对路径）+ 自然语言行范围；**不含** `languageId`、**不含**选区正文；
  - 用户可补充提问后发送。
- 空选区：轻量提示，不产生空引用消息。
- `@相对路径` / `@绝对路径`：
  - 发送前校验路径存在且在工作区内；
  - 合法则原样纳入 user 消息；**必须不**读取并附加文件内容；
  - 无效路径明确提示，不发送该消息。
- 含一个或多个有效引用的有效交互：**每个**引用路径 **必须** 在最终回答前至少出现一次读取工具调用（AC-3a）。
- ide 缺少文件引用引导时，扩展激活后补齐等效配置（AC-3b）。

#### B. 变更感知与记录

- 扩展须稳定识别 DSH 产生的创建/修改/删除（机制由 Spike 锁定后实现；Spike 未完成前必须不开始本区域实现 Phase）。
- 每条变更至少含：相对路径、类型（created/modified/deleted）、变更前后内容（或等价可 diff/可撤销数据）、状态（unreviewed/reviewed/reverted）、来源消息 ID、时间。
- 同执行同文件多次写入 → 对外一条合并最终差异。
- 排除：二进制、超大小阈值、构建/生成目录（gitignore 思路）、工作区外写入。
- 禁止将用户手动编辑、格式化器、其它扩展写入标为 DSH 变更。

#### C. 变更展示

- 列表挂靠触发该执行的助手消息下方。
- 条目：路径、类型、+N/−M、状态；可折叠为「改动了 N 个文件」；无变更时不展示空列表，必须一句说明。
- 内嵌 diff：行号、增删着色、语法高亮；XSS 安全（不执行脚本、不加载外链、默认转义）。
- 单击条目：打开对应文件并尽量定位到首个变更行。

#### D. 审阅与撤销

- 「标记已审阅」仅改状态，不写盘；文案不得暗示「未写入 / 待批准」。
- 「撤销此文件」恢复变更前状态；打开中的文件经文档层；成功 → reverted；失败 → 错误且状态不变。
- 新建撤销：二次确认后删除。
- 删除撤销：按旧内容恢复；已存在同名文件则先冲突提示。
- 变更后又被用户/其它工具修改：撤销前提示将丢失后续改动，确认后执行。
- 多文件：勾选批量或「全部撤销」；逐文件结果；部分失败如实呈现。
- 已撤销后同一文件再次被 DSH 修改 → 新变更记录，不与旧 reverted 混同。

#### E. 溯源与隔离

- 变更 → 来源消息；助手消息 → 其变更列表。
- 不同执行列表视觉隔离。
- 历史回放：至少路径与统计可见（完整 diff 是否持久化由 Design 在本地快照生命周期中规定）。

#### F. 前序共存与回归

- 与 AC-30 摘要入口共存（D-9）；chat-ready Must 不回退（AC-25）。

### Out of Scope

| 排除项 | 说明 |
|--------|------|
| 写盘前审批 / 拦截 DSH 写入 | 不改变「DSH 直接写工作区」模型 |
| 文件内容内联进 user 消息 | 代码引用以指针形式发送；DSH 按需读取磁盘（D-11） |
| 编辑器 dirty buffer 同步 | 不读 buffer 内容进消息；触发前自动保存保证磁盘一致 |
| `@path:start-end` 扩展文法 | 行范围仅自然语言；官方 `@路径` 不变 |
| 结构化 code-context ContentBlock | 不新增 SDK 内容块类型 |
| 全库语义检索 / embedding / 自动上下文推断 | 仅显式选区与 `@路径` |
| `@` 文件自动补全下拉 UI | 仅解析用户手输路径 |
| Cmd+L / 全局唤起 / 编辑器内浮动对话框 | 独立产品设计 |
| Timeline 视图重构 | 仅消息附属变更列表；Timeline 可继续作弱化面 |
| 多轮自动冲突合并 UI | 不做自动合并 |
| Git 集成（git diff / commit / branch 驱动） | 快照与撤销基于扩展本地内容 |
| 在 diff 视图上直接编辑后再应用 | 不做 |
| 按文件类型/语言过滤变更列表 | D-8 砍掉 |
| 同文件多版本中间快照恢复点 | D-8 砍掉 |
| 修改 agent-loop / 工具写盘语义 | 禁止 |
| 把变更快照写入权威会话日志 | 禁止 |
| 将 AC-30 升格为审阅/撤销主 UI | AC-30 保留；主路径为消息附属列表 |

## 验收标准（EARS 格式）

优先级：全部 `[Must]`。每条可独立判 ✅/❌。

### A. 代码引用

**AC-1:** `[Must]` **事件驱动型** — **当** 编辑器存在非空选区且用户触发「向 DSH 提问选区」（命令或右键）**时**，系统 **必须** 先检查目标文档是否脏；**如果** 脏，**那么** 系统 **必须** 先自动保存该文档；**如果** 保存失败，**那么** 系统 **必须不** 生成引用，且 **必须** 提示用户手动保存后重试；**如果** 保存成功或不脏，**那么** 系统 **必须** 激活或复用 DSH 对话，并在输入框预填仅含工作区内路径的官方 `@路径` 文本与自然语言行范围（例如 `@src/foo.ts 的 3-40 行`），**必须不** 预填选区正文或 `languageId`；用户 **必须** 能直接补充提问并发送。

**AC-2:** `[Must]` **不期望行为型** — **如果** 选区为空且用户触发该命令或右键，**那么** 系统 **必须不** 生成引用消息，且 **必须** 给出轻量提示。

**AC-3:** `[Must]` **事件驱动型** — **当** 用户发送含 `@路径`（相对或绝对）的消息 **时**，系统 **必须** 在发送前校验路径是否存在且位于当前工作区内；**如果** 路径无效，**那么** 系统 **必须** 给出明确提示，且 **必须不** 发送该消息；**如果** 路径有效，**那么** 系统 **必须** 将引用文本原样纳入 user 消息发送，且 **必须不** 在发送前读取并附加任何文件内容。

**AC-3a:** `[Must]` **事件驱动型（端到端读取）** — **当** 一条 user 消息包含**一个或多个**有效代码引用并已提交给 DSH **时**，一次有效交互 **必须** 满足：**该消息中的每个有效引用路径**都在该轮会话日志中对应**至少一次**读取工具调用（如 `read`），且这些调用 **全部** 发生在模型产生最终回答**之前**。验证采用 stub 模型：遇引用可构造读取调用；**凡任一有效引用路径在最终回答前缺少对应读取调用的交互一律判失败**。多引用时 **不** 约束各 path 的读取先后顺序（并发或任意顺序均可）。

> **验证边界（P1）**：AC-3a 的 stub 通过 **仅** 证明管线层契约成立（含引用时 answer 前须覆盖每个路径的 read），**不** 替代真实模型行为抽测；真模型在单引用与多文件对比等典型场景下的 read 行为须另行记录观测结果（非门禁观测项，不得单独作为 Must 唯一证据）。

**AC-3b:** `[Must]` **配置型** — **当** ide profile 未挂载等效于 `FILE_REFERENCE_PROMPT` 的引导配置 **时**，扩展 **必须** 在激活后补齐等效配置，使模型能够将消息中的代码引用理解为「可用文件读取工具按需获取磁盘内容」；**禁止**通过修改 agent-loop 实现。

**AC-4:** `[Must]` **普遍型** — 消息中出现的每条代码引用 **必须** 能被用户识别为具体文件；UI 可以使用折叠或链接展示 `@路径`，行范围可作为描述文本；底层消息 **必须不** 包含引用文件的正文。点击引用卡打开文件时，定位行号 **必须** 来自扩展在预填时记录的选区元数据（若有），**必须不** 依赖解析自然语言行范围文法。

### B. 变更感知

**AC-5:** `[Must]` **普遍型** — DSH 在当前工作区执行期间对文件产生创建/修改/删除且通过归属判定时，系统 **必须** 为该文件生成变更记录，并关联到触发执行的助手消息。

**AC-6:** `[Must]` **事件驱动型** — **当** 一条 DSH 任务完成 **时**，对话视图 **必须** 在该消息下方展示对应变更列表；**如果** 本次执行无工作区文件变更，**那么** 系统 **必须不** 展示空列表骨架，且 **必须** 显示一句无变更说明（文案可文档化）。

**AC-7:** `[Must]` **普遍型** — 变更记录 **必须** 至少含：路径、类型、diff 数据（或等价可 diff/可撤销数据）、状态（unreviewed/reviewed/reverted）、来源消息 ID、时间。

**AC-8:** `[Must]` **不期望行为型** — **如果** 写入为二进制、超过大小阈值、构建/生成目录（gitignore 思路）、或工作区外路径，**那么** 该写入 **必须不** 出现在变更列表。

**AC-9:** `[Must]` **不期望行为型** — 系统 **必须不** 将非 DSH 来源修改（用户手动编辑、格式化器、其它扩展）标记为 DSH 变更；验收 **必须** 含至少一条误报否定用例。

### C. 展示与审阅

**AC-10:** `[Must]` **状态驱动型** — **在** 变更状态为 unreviewed **期间**，UI **必须不** 以任何文案暗示该文件「尚未写入」或「等待批准」。

**AC-11:** `[Must]` **事件驱动型** — **当** 用户点击「标记已审阅」**时**，状态 **必须** 变为 reviewed，且系统 **必须不** 对该文件或任何工作区文件产生写入。

**AC-12:** `[Must]` **普遍型** — 变更列表 **必须** 支持逐文件查看 diff；多文件时 **必须** 支持折叠与展开。

**AC-12a:** `[Must]` **事件驱动型** — **当** 用户单击变更条目 **时**，系统 **必须** 打开对应文件，并 **必须** 尽量定位到首个变更行；**如果** 无法定位变更行，**那么** 系统 **必须** 至少打开该文件。

### D. 撤销

**AC-13:** `[Must]` **事件驱动型** — **当** 用户点击「撤销此文件」且无冲突门禁拦截 **时**，系统 **必须** 将该文件恢复至该变更发生前的状态，并将状态置为 reverted；**如果** 恢复失败，**那么** 系统 **必须** 展示错误，且状态 **必须不** 变为 reverted。

**AC-14:** `[Must]` **事件驱动型** — **当** 对 DSH 新建的文件执行撤销 **时**，系统 **必须** 经用户二次确认后删除该文件。

**AC-15:** `[Must]` **事件驱动型** — **当** 对 DSH 删除的文件执行撤销 **时**，系统 **必须** 按旧内容重新创建；**如果** 当前已存在同名文件，**那么** 系统 **必须** 先提示冲突再操作。

**AC-16:** `[Must]` **不期望行为型** — 撤销 **必须不** 阻止后续 DSH 再次修改同一文件；再次修改 **必须** 记为新变更，**必须不** 与已 reverted 记录混同。

**AC-17:** `[Must]` **事件驱动型** — **当** 用户对「该变更之后又被用户或其他工具修改过」的目标文件执行撤销 **时**，系统 **必须** 在执行前提示「撤销将丢失后续改动」（或文档化等价），经确认后执行；用户取消则 **必须不** 写盘。

**AC-18:** `[Must]` **普遍型** — 多文件撤销（勾选批量或「全部撤销」）**必须** 逐文件返回结果；部分失败时 **必须** 逐项呈现成功与失败。

### E. 溯源与隔离

**AC-19:** `[Must]` **普遍型** — 每条变更 **必须** 能从 UI 定位到来源消息；每条助手消息 **必须** 能展示其产生的变更列表。

**AC-20:** `[Must]` **普遍型** — 同一 DSH 执行中多次写入同一文件时，UI **必须** 展示为合并后的最终差异；中间历史 **必须不** 作为默认展示内容。

**AC-21:** `[Must]` **不期望行为型** — 不同 DSH 执行产生的变更列表 **必须不** 交叉混合，且 **必须** 可视觉区分。

**AC-22:** `[Must]` **普遍型** — 历史消息回放时，消息关联的变更列表（至少文件路径与统计）**必须** 可见。

### F. 安全

**AC-23:** `[Must]` **普遍型** — 变更 diff 渲染 **必须不** 执行脚本、**必须不** 加载外部资源，且默认转义；验收 **必须** 含至少一条恶意载荷否定用例（L2/L3）。

**AC-24:** `[Must]` **不期望行为型** — 变更快照及文件旧内容 **必须不** 以明文写入扩展日志；日志 **仅可** 记录元数据与统计。

### G. 前序不回退

**AC-25:** `[Must]` **普遍型** — 本 Feature **必须不** 破坏前序 chat-ready Must（自动建连、对话底盘、新建 chrome、AC-30 摘要入口可点等）；合入后回归抽测 **必须** 通过。

## 约束

- 遵守 `.specdev/specs/vscode-dsh-code-context-diff/constitution.md`。

- 归属：宁可漏记不可误记；必须有误报否定用例（AC-9）。
- 验证以 L2/L3 为主；L4 仅辅助；L4 不得作为 Must 唯一证据；AC-3a **必须**有 L2 stub 证据。
- 与 AC-30 / Timeline 共存语义由 Design 规定，必须不双轨矛盾。
- Spike 门禁：未完成归属/快照可行性 Spike 前，必须不开始「变更感知 / 快照 / 撤销」实现 Phase；代码引用可与 Spike 并行。

## 风险/假设

- **A-1：** 前序 chat-ready 行为面已按规格验收。
