## 1. 触发来源

`reviewer-visual` 的 round-2 报告（`review-visual.md`，判决 `N/A`）记录了一个**它无权判决**的事实：5 张截图 **md5 相同**。
调度者据此独立复核，确认成立并**扩大了结论**（见 §2）。视觉视角判 `N/A` 是正确的（本 Phase `ui: false`，无冻结基准）——**该发现属取证有效性问题，不属视觉一致性问题**。

## 2. 已独立核实的事实（调度者实测，非推测）

### 2.1 本轮用于验收的 PASS 运行，其截图不是五步的证据

| 项 | 值 |
|---|---|
| 运行 | `20260916T135716Z-1864170`（`layer-v-report-meta.json` 的 `runId`） |
| `display` | `{mode: "reuse", value: ":1", xvfb: null}` |
| 5 张 PNG | `step-1-host-started` … `step-5-native-diff`，**md5 全为 `013661a1487c30c76574cde59b90ef39`**，各 `127977` 字节 |
| mtime | `21:57:31.701` / `:32.373` / `:34.133` / `:43.092` / `:49.340` —— **捕获时刻确实分散**（故「拍到了 5 次」为真） |
| 画面内容 | **3840×1080**（作者双屏桌面尺寸）；主色 `(25,1,22)` 仅占 **1.6%**、3253 种颜色、行方差均值 **3.3** → **桌面壁纸**，无窗口结构 |

### 2.2 同一机制在 `xvfb` 模式下能拍到真正的 EDH 窗口

| 项 | `xvfb` 模式运行 `20260916T134549Z-1807615` |
|---|---|
| 5 张 PNG | **5 个不同 md5**，尺寸 `154571` / `154721` / `159035` / `174450` / `176255` |
| 画面内容 | **1600×1000**；主色 `(16,16,16)` 占 **45.78%**、`(0,0,0)` 19.0%、`(21,21,21)` 11.43%（= VS Code 深色主题底色）；行方差均值 **16.5** → **真实 UI 结构** |

**跨运行统计**（`test-artifacts/layer-v/.archive/*/`）：在被检查的这批运行中，`reuse` 模式为 `unique_md5=1`（5 张全同）、`xvfb` 模式为 `unique_md5=5`（5 张各异）。

> ⚠️ **本节已被 `verifier` 的独立验证修正（2026-09-17）**：上句**不等于**「`reuse` 必然退化」。verifier 在归档中找到了**`reuse` 却 5 张各异**的运行 → 故**判据不能是 `display.mode` 的名字**，而应是**当次运行的 distinct md5 数**（即「本次截图彼此是否可区分」）。本文件下文与 HG-3 的呈报均以修正后的判据为准 —— 感谢该独立复核，原表述会造成「凡 `reuse` 即无效」的过度归因。
>
> 另经 verifier 量化：`reuse` 退化时相邻步像素差**全为 0.0**（零信息量），`xvfb` 时为 0.193 / 1.334 / 1.170 / 2.975。

**跨运行统计**（`test-artifacts/layer-v/.archive/*/`）：`reuse` 模式运行**多数**为 `unique_md5=1`（5 张全同）；`xvfb` 模式运行为 `unique_md5=5`（5 张各异）。

### 2.3 两处加剧因素

1. **`artifact-index.md` **不记录** `display.mode`**（`grep -n 'reuse\|xvfb\|display' artifact-index.md` → 0 命中）。该索引是 AC-33 / AD-7 指定的**唯一被 git 追踪**的可追溯载体 → **读者无法分辨哪次运行的截图是有效证据**。
2. **唯一产出有效截图的那次 `xvfb` 运行跑在旧 bundle 上**（implementer 主动披露于 `implementation.md` §7.2 注）。
   ⇒ ~~**目前没有任何一次运行同时满足「跑的是当前源码」+「结论 PASS」+「截图有效」三个条件。**~~

>
> verifier 按委托要求在**重建之后**重跑了 `xvfb` 分支，产生了归档运行 `20260916T165522Z-2238377`（`2026-09-16T16:55:22Z` = 本地 `09-17 00:55:22`），该运行**同时满足三条件**（调度者已独立复核）：
>
> | 条件 | 该运行的实测值 |

> | 结论 PASS | `conclusion: "PASS"`（`layer-v-status.json` / `run-summary.json` / `layer-v-report-meta.json` 三处一致） |

> **因此第 2 点「三条件无交集」的结论作废。** 但**§3 的规格缺口定性不变**：`reuse`（AC-28 的首选分支）下截图仍可能退化为桌面壁纸，且 `artifact-index.md` 仍不记录 `display.mode` —— 缺口的根因是「AC-26 缺少『截图必须呈现 EDH 界面』这一判据、且与 AC-28 的首选分支之间无核对环节」，**而非**「从未取得过有效截图」。本 Phase **已取得**有效视觉证据（上面那次），但该证据的取得**依赖人工/委派时主动选择 `xvfb`**，不是流程保证。

## 3. 定性：这是**规格缺口**，不是实施者过失

- **AC-28 明文要求**「脚本 **必须** 优先复用已存在的可达 `DISPLAY`（`display.mode === "reuse"`）」，`DISPLAY=:1` 可达 → 走 `reuse` **完全合规**。implementer 无过错。
- **AC-26 的验证方法**（`spec.md:187`）只有四判据：5 个文件 / 稳定命名 / 合法 PNG + 大小下限 / 被仓库根规则 ignore + 不在 `git status`。**它无法区分「拍到了该步骤」与「拍到了任意画面」** → 该 AC 在**形式**上通过。
- 但 `design.md` AD-8 为「必须提供显示」给出的**理由**是：「无显示时无法产出截图证据，报 PASS 等于伪造通过」（`design.md:219`）。截图在 `reuse` 模式下**不是证据** → 该理由所保护的意图**未被兑现**。
- ⇒ 缺口在**规格层**：AC-26 缺少「截图必须**呈现 EDH 界面本身**（而非该显示上的任意画面）」这一判据，而 AC-28 的首选分支（`reuse`）恰恰使该判据无法自动成立 —— 且二者之间**没有任何环节**做过核对。
