## 新增发现（本轮）

### 🟡 New-S1 — dead review-item citations in this round's new code

`apps/vscode-dsh/tests/node-env-guard.spec.ts:240` `it('probes a process-exec-path candidate in the Electron mode the spawn will use (S9)', …)`, `:629` `it('re-reads the setting on every start instead of caching the first value (S5, AD-9)', …)`, and the comment at `:664-665` `// M2: the class crosses the host → orchestrator hop intact, …` cite **review-report item codes**, not spec or design identifiers.

- `(AD-9)` resolves to `design.md`; `(S9)` / `(S5)` / `M2` resolve only to the round-1 review report, which lives in `.archive/`. A reader of the shipped test cannot resolve them, which is exactly the "dead design-session citation / audit item code" class the repo's prose standard forbids (`docs/AGENTS.md`, Writing rules: comments "state complete contracts, not reasoning transcripts … delete narration, test walkthroughs, review analysis, and code restatement").
- Not an existing convention: `git grep -nE "\((M[0-9]|S[0-9]+)[,)]"` over tracked `*.ts`/`*.tsx` finds only unrelated session-fixture identifiers (`S1`/`S2` values in `packages/api/session-controller/tests/manager.client.spec.ts`), never a review-item code.
- Smallest fix: keep the behavioural half and drop the citation — `(S9)` → describe the Electron probe mode; `(S5, AD-9)` → `(AD-9)`; `// M2: ` → state the invariant ("the class must survive the hop so a consumer attributes the failure to the Node environment"). `AD-`/`AC-` citations are the established house style in this app (35 in `extension.ts`, 58 in `conversation-controller.ts`) and need no change.
- Severity: convention only. No gate catches it and no acceptance criterion depends on it.

### 🟡 New-S2 — the new non-string `dsh.nodeBin` path lands in the generic error class

`extension.ts:2173-2185` throws a plain `Error` for a non-string setting; `createStartHostPort` rethrows the same `Error` unchanged (`:2276-2278`); `startErrorKindOf` (`auto-start-orchestrator.ts:47-55`) finds no `kind` and returns `'process-failed'`.

- So the one failure path this round added to the setting source is classified as a dsh-side process failure on the structured channel, while the path-validation failure from the same source is classified `node-environment` — the asymmetry M2 exists to remove, on a new branch. `node-env-guard.spec.ts:673-686` asserts `state === 'failed'`, the absence of a host start, and that the message names `dsh.nodeBin` and `string`, but does **not** assert `errorKind`, so the behaviour is unasserted as well as unrecorded.
- Scope caveat (why this is should-fix and not must-fix): no AC enumerates a non-string setting. AC-10's invalid-setting branches are "指向的路径无效或缺少 AC-4 所列 API"; `spec.md:106`'s boundary list covers blank / non-empty-but-invalid paths, not types. The user-visible text is still environment-scoped, naming `dsh.nodeBin` and the expected type, so AC-9's user-facing half is not breached. `implementation.md` §5 item 11 records *why* the value throws early but not why it keeps the generic class.
- Either fix: throw a `HostStartError('node-environment', …)`-shaped error (or have `readNodeBinSetting` surface a `kind`) and assert `errorKind`, **or** record the choice in §5 with the reason. Both are one-line-scale decisions; the orchestrator may also file it as Phase 2 debt, since Phase 2 owns the failure vocabulary.
