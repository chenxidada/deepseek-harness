## 观察项（不阻塞，供后续参考）

- **O-1 `setSink()` 是死公共 API**（三轮一致关注）。非桩、非缺陷；建议后续清理时删除（构造器选项才是产品路径）或在 JSDoc 声明其所有者。**注意**：保留一个无消费者的未测公共 mutator，等于邀请未来调用方静默改道 channel。correctness 明确论证其非 §should-fix，故不计入本区上表。
- **O-2 `DEBT-010` 的残余缺口范围划得正确**（correctness 🟢-2 确认）：接线握手后死亡需要 `phase` 第三成员 → AD-14 决策 11 强制递增 `schemaVersion` → 打破 Phase 3 的 `=== 1` 精确字段断言。以「已声明 Phase-3 触发条件」的登记方式处置是对的；唯一风险（Phase 3 冒烟把空记录数组误读为「无失败」）已被注册表明文点名。
- **O-3 词表用例 `host-diagnostics.spec.ts:437-451` 属自比对**（同义反复，只在有人改字面量时才失败）。真正的强制来自三处：产出的键集（`:136`）、显式 `invalid-setting → null` 断言（`:458`）、以及 `Record<HostFailureKind, StartErrorKind>` 的编译期穷尽性（`host-diagnostics.ts:209`）—— 故契约**确实**被强制。若将来导出运行期词表，`:437` 应改为与它比对。
- **O-4 脱敏落在存储边界而非渲染边界**（correctness 🟢-4）：`stderrTail` 逐行经 `redact` 后才入存储（`host-diagnostics.ts:368`），故只出现在 stderr 行内的密文也无法经渲染路径到达 channel。方向正确（构造上 fail-safe，而非依赖调用点纪律），这正是 AC-21 四表面断言有意义的原因。
- **O-5 `tests/zz-rc2-probe.spec.ts` 曾被同级审查者留在工作区**（connectivity 报出）。**已核实：该文件当前不存在**，审查者收工自清，提交集干净。
- **O-6 `pnpm-lock.yaml` 有与本 Phase 无关的漂移**（`tsdown` 新增、`vite@6.4.3 → 8.0.16`、他包 importers 条目重排）。**不得进 Phase 2 提交集**。
