## 检查重点结论

### 1. P-接续 vs P-标明
- 入口：`intent` → `presentationForIntent` 二分；controller 分派 `applyContinueSwitch` vs `applyBranchMark`。
- P-接续强制父 `replay` + E2 Sets + Continue sealed + reject-send；P-标明不改父 mode、不下发 parentReadonly。
- 与 X3 / AD-CUX-5 / AC-31 vs AC-60 一致。

### 2. E2 决策态在 Host
- 权威：`registry.mode`、`parentReadonlySessions`、`continueSealedSessions`、`continueChromeFor`、`sendPrompt` replay 闸。
- 探针：`hostProbesForActive` → `panel/state.probes` → Webview `mirrorHostDecisions`（只读）。
- 符合 §7.2 与 GAP-CUX-002 关闭条件；层 B 明确拒「仍 live 无探针」。

### 3. Fork 三件套分层
```
Webview action → ConversationController.forkFromClosedTurn
  → resolveClosedTurnBoundary (fork-orchestrator)
  → SessionHost.forkSession → bridge session/fork → sdkSessionFork
  → applyContinueSwitch | applyBranchMark
```
- 产品边界闸在 Host；传输镜像 cancel；SDK 产出 prompt-ready child。分层清晰。

### 4. 未越界 phase-6
- 无搜索 UI、无 path→session 索引、无 `searchSessions` Host API。范围干净。

### 5. GAP-CUX-002 关闭是否符合设计
- 缺口本是「协议位就绪、产品路径从不推 probes」。本 Phase 在 P-接续后由 Host `pushFullState` 写入 `parentReadonly`/`continueSealed`，并封印 Continue chrome。
- registry 移入「已解决」与设计/Phase Entry「a) 本 Phase 填实」一致。

### 6. 已记录偏差（不升格 MUST-FIX）
| 偏差 | 与设计关系 | 设计一致性判定 |
|------|-----------|----------------|
| SDK `agents.create`+seed 而非直接 `sessions.fork` | Bridge 示意图字面差；seed/lineage 等价；web Remote 同模式 | ✅ 可接受；建议后续修订 design Bridge 一行以免误导 |
| retry/edit prior-cut + child `promptTab` | ForkRequest 注释「seed 含该 user」字面差；产品「丢弃其后并重发」达成 | ✅ 可接受；已写入 implementation 偏差 2/3 |
